## 📖 О проекте

**Divine** — это 2D-симулятор автоматизации производства, объединяющий механику фабричной логистики (в духе *Factorio* и *Shapez*) с процедурной генерацией артефактов и модификаторов (префиксы, суффиксы и тиры T1–T5 в духе *Path of Exile*), усиливающих заводы через Алтари.

Игрок проектирует логистические цепочки, перерабатывает руду и эссенции, куёт артефакты, накладывая на них различные аффиксы, и устанавливает их в Алтари, многократно ускоряя и модифицируя близлежащие заводы.

## ✨ Ключевые особенности

### 🏭 1. Логистика и производство
- **Сетка и связи (Pipes/Flow):** Прямая маршрутизация ресурсов между портами зданий без задержек пакетов.
- **Компактные сплиттеры:** Минималистичные сплиттеры 1x2 с динамическими световыми линиями и автоматической трассировкой входящих ресурсов.
- **Автоматический баланс:** Конвейерная логика моментально перенаправляет потоки ресурсов по доступным приемникам.

### 🔮 2. Система артефактов и PoE-аффиксов
- **Кузница болванок (`Shell Forge`):** Создание базовых белых артефактов (`Runesteel Amulet`).
- **Инфьюзер (`Shell Infuser`):** Зачарование белой болванки 3–6 случайными аффиксами за Мана-эссенцию.
- **Тиры и теги (T1–T5):** Аффиксы имеют градации редкости и привязаны к тегам построек (`[Miner]`, `[Smelter]`, `[Assembler]` и др.).
- **Очиститель (`Purifier`):** Стирание аффиксов обратно в белую болванку для реролла.
- **Алтари (`Artifact Altar`):** Проецируют радиус действия (AoE), усиливая только те здания в округе, которые соответствуют тегам вставленного артефакта.
- **Хранилище (`Vault Gateway`):** Двунаправленный шлюз между конвейерами и глобальным инвентарем артефактов.

### 🚀 3. Высокопроизводительный движок рендеринга
- **MultiMesh GPU Instancing:** Все здания, порты и панели группируются и отрисовываются за единичные draw-call'ы через `MultiMeshInstance2D`.
- **Frustum & Dynamic LOD Culling:** Автоматическое отсечение невидимых объектов за пределами камеры с оптимизацией при отдалении зума.
- **Плавные 60+ FPS:** Способность симулировать и рендерить тысячи построек одновременно без просадок кадров.

### 📈 4. Прогрессия и мета-геймплей
- **Портал и Майлстоуны:** Сдача ресурсов в Портал для открытия новых тиров технологий и зданий.
- **Магазин апгрейдов:** Глобальные улучшения скорости фабрики, добычи и пропускной способности связей.
- **Шаблоны фабрик (Templates):** Создание, переключение и сброс независимых макетов заводов на лету.
- **Оффлайн-добыча:** Расчет накопленной продукции и кредитов за время отсутствия игрока при перезапуске игры.

## 🎮 Управление (Controls)

| Действие | Управление |
|---|---|
| **Выбор / Осмотр здания** | `ЛКМ` по зданию |
| **Снять выделение** | `ЛКМ` по пустому полю |
| **Создать связь (Link)** | `ПКМ` по зданию/порту-источнику $\rightarrow$ `ЛКМ` по зданию-цели |
| **Перемещение здания** | Зажать `ЛКМ` на здании и перетащить |
| **Рамочное выделение (Box Select)** | `Ctrl` + зажать `ЛКМ` и потянуть рамку |
| **Добавочное выделение** | `Ctrl` + `Shift` + `ЛКМ` |
| **Перемещение группы** | Потянуть за любое здание из выделенной группы |
| **Потоковое строительство (Stream Build)** | Зажать `Shift` при размещении зданий |
| **Панорамирование камеры** | Зажать `ЛКМ` на пустом поле или колесико мыши |
| **Масштабирование (Zoom)** | Вращение колесика мыши |
| **Удаление здания** | Клавиша `Delete` (или режим Снос в HUD) |

| **Infuser** | 3x3 | Насыщение материалов магической энергией (рунесталь) |
| **Splitter (2 / 3)** | 1x2 | Разделение потока ресурсов на 2 или 3 выхода |
| **Seller** | 2x2 | Продажа продукции за Кредиты |
| **Portal** | 3x3 | Прием ресурсов для закрытия фаз майлстоунов |
| **Shell Forge** | 3x3 | Ковка пустых заготовок артефактов |
| **Shell Infuser** | 4x4 | Нанесение 3–6 случайных аффиксов за эссенцию |
| **Purifier** | 3x3 | Очистка артефакта обратно до белой болванки |
| **Artifact Altar** | 4x4 | Установка артефакта и бафф зоны вокруг |
| **Vault Gateway** | 3x3 | Двунаправленный шлюз хранилища (Store / Retrieve) |
| **The Void** | 3x3 | Безопасная утилизация и уничтожение любых излишков |

## 🏗️ Архитектура кодовой базы

Проект строго следует принципам **Data-Driven Architecture**:

```
scripts/
├── core/
│   ├── state/          # Модели чистых данных (Game, Factory, Building, ItemSlot, ItemData)
│   └── systems/        # Статические чистые системы логики (BuildingSystem, FlowSystem, ModifierSystem...)
├── resources/          # Godot Resource типы (BuildingCostData, MilestoneData, UpgradeData)
├── visual/             # Отображение, ввод и интерфейсы (BuildingRenderer, HUD, Inspector...)
└── tools/              # Скрипты автотестов и утилиты
```

- **Разделение данных и логики:** Объекты состояния (`scripts/core/state/`) не зависят от узлов сцены (`Node2D`) и содержат чистые структуры данных.
- **Статические системы:** Системы (`scripts/core/systems/`) оперируют только над объектами состояния и не хранят скрытого мутабельного состояния между тиками.
- **Слоты ресурсов (`ItemSlot`):** Буферы зданий стандартизированы через слоты с поддержкой ограничений по тегам и метаданных полезной нагрузки (`payload`).

## 🚀 Запуск и тестирование

### Требования
- **ОС:** Windows (ПК, управление клавиатурой и мышью).
- **Godot Engine 4.7+** (режим рендеринга Mobile/D3D12).

### Запуск проекта
1. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/DisKass/Divine.git
   ```
2. Откройте проект в редакторе Godot и запустите главную сцену (`F5` или `res://scenes/main_game.tscn`).

### Запуск тестов
Для быстрой верификации систем аффиксов, слотов и логики зданий без запуска GUI:
```bash
godot --headless --script scripts/tools/test_affix_and_buildings.gd
```
