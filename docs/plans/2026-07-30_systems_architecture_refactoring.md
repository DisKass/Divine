# План рефакторинга: Архитектура "Систем" и визуальная оптимизация

Этот план направлен на масштабный рефакторинг проекта с целью перехода на Data-Driven Systems в ядре и разгрузки разросшихся "мастер-классов" в визуальном слое.

В ходе рефакторинга мы полностью откажемся от сокращений (вроде `b_id`, `vis`, `tpl_dict`) в пользу полных названий для максимальной ясности кода во всех затрагиваемых файлах.

---

## Часть 1: Переход ядра (Core) на архитектуру "Систем"

Эта часть сфокусирована исключительно на логике симуляции фабрики и затрагивает `core`. Текущий монолитный класс `factory_network.gd` будет разделен на изолированные Системы.

1. **Разделение логики `factory_network.gd`:**
   - **`GridSystem`**: Отвечает за домен пространственной организации. Проверки `is_area_free`, размещение зданий на сетке, перемещение, коллизии.
   - **`FlowSystem`**: Отвечает за домен логистики. Перемещение ресурсов по связям между зданиями.
   - **`ProductionSystem`**: Отвечает за домен крафта. Обработка рецептов внутри зданий.
   - Удаление старого `factory_network.gd`.

2. **Очистка `BuildingData`:**
   - Превращение в чистый контейнер данных (State).
   - Избавление от сокращений в именах переменных.

3. **Оркестрация (`SimulationTicker`):**
   - Обновление `SimulationTicker` для последовательного вызова новых Систем (сначала `GridSystem`, затем `ProductionSystem`, затем `FlowSystem`).
   - Сохранение текущих оптимизаций (кешированные массивы), но их перемещение внутрь соответствующих Систем.

4. **Тестирование Части 1:**
   - Обновление и запуск автоматических тестов в `core/test_*` (особенно `test_factory_flow.gd` и `test_splitters.gd`), чтобы гарантировать, что симуляция не сломалась.

---

## Часть 2: Визуальный слой, Управление и Голограммы

Эта часть сфокусирована на разгрузке разросшихся скриптов UI и управления (`main_game.gd`, `input_controller.gd`, `building_renderer.gd`).

1. **Голограммы (`HologramManager`):**
   - Создание новой системы для универсального отображения полупрозрачных "призраков" зданий.
   - Интеграция `HologramManager` для замены дублирующегося кода превью в режимах одиночного строительства и копирования.

2. **Инпуты (`input_controller.gd`):**
   - Внедрение паттерна "Состояние" (State) для режимов мыши (`InspectState`, `BuildState`, `LinkState`, `CopyState`).
   - `input_controller.gd` станет легкой стейт-машиной, делегирующей события.

3. **Координатор (`main_game.gd`):**
   - Вынос логики создания UI в `GameUIManager`.
   - Вынос логики инстанцирования визуальных нод зданий в `VisualSpawner`.
   - `main_game.gd` станет чистой точкой входа (Game Loop).

4. **Рендерер (`building_renderer.gd`):**
   - Выделение логики динамических оверлеев (рамки при наведении, иконки ошибок) в `OverlayRenderer.gd`.
   - Оставление в `building_renderer.gd` только базовой отрисовки сетки спрайтов.

5. **Тестирование Части 2:**
   - Ручная проверка всех режимов мыши (Build, Link, Copy, Demolish).
   - Проверка корректности визуальных оверлеев и голограмм.
